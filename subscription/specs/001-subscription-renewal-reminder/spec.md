# Feature Specification: Subscription Renewal Reminder

**Feature Branch**: `001-subscription-renewal-reminder`

**Created**: 2026-07-29

**Status**: Draft

**Input**: User description: "通过用户手动输入自己在某些软件订阅的套餐信息，到期前自动发送微信消息提醒即将自动续费"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 录入订阅并收到续费提醒 (Priority: P1)

用户手动录入一个正在使用的软件订阅，包括软件或服务名称、套餐名称、下一次自动续费日期、计费周期和提醒时间。到达设定的提醒时间后，用户通过已绑定的微信接收即将自动续费的消息，从而有时间决定继续订阅还是自行取消。

**Why this priority**: 这是产品解决“忘记取消导致意外扣费”问题的最小完整闭环，也是首版必须交付的核心价值。

**Independent Test**: 创建一个即将在测试时间窗口内续费的订阅，并验证微信账号只收到一条包含正确订阅信息和续费日期的提醒，即可独立验证该故事。

**Acceptance Scenarios**:

1. **Given** 用户已绑定可接收提醒的微信且填写了有效订阅信息，**When** 用户保存订阅，**Then** 系统展示该订阅及下一次提醒时间。
2. **Given** 一个启用中的自动续费订阅已到达提醒时间，**When** 系统处理该提醒，**Then** 用户的微信收到包含软件或服务名称、套餐名称、预计续费日期和金额（如已填写）的提醒。
3. **Given** 同一订阅的同一次续费已成功发送某个提醒，**When** 系统再次检查待发送提醒，**Then** 不重复发送该提醒。
4. **Given** 用户保存的订阅将在默认提前天数以内续费且尚未提醒，**When** 保存完成，**Then** 系统尽快安排一次提醒，并明确展示预计发送时间。

---

### User Story 2 - 管理订阅与提醒设置 (Priority: P2)

用户可以集中查看自己的多个订阅，修改套餐、金额、续费日期、计费周期和提醒时间，也可以在取消订阅后停用该条记录，避免继续收到无效提醒。

**Why this priority**: 订阅信息和用户决策会变化；如果不能及时修正或停用，提醒很快会失去可信度。

**Independent Test**: 创建多个订阅，分别执行编辑、停用和重新启用，并验证列表信息与后续提醒安排同步变化，即可独立验证该故事。

**Acceptance Scenarios**:

1. **Given** 用户已有多个订阅，**When** 用户查看订阅列表，**Then** 可以识别每项订阅的服务名称、状态、下一次续费日期和下一次提醒时间。
2. **Given** 用户修改下一次续费日期或提醒时间，**When** 保存修改，**Then** 旧的未发送提醒失效，并按新信息生成提醒安排。
3. **Given** 用户已取消某项外部订阅，**When** 用户将该记录停用，**Then** 系统不再为其发送后续提醒，同时保留该记录供用户查看或重新启用。
4. **Given** 一个周期性订阅仍处于启用状态，**When** 当前续费日期过去，**Then** 系统按计费周期推算并展示下一次续费日期及对应提醒时间。

---

### User Story 3 - 了解提醒发送状态 (Priority: P3)

用户可以查看每次提醒的待发送、已发送或失败状态。当微信提醒暂时发送失败时，系统会自动重试，并让用户知道最终结果，避免用户误以为已经收到提醒。

**Why this priority**: 提醒产品的可信度取决于投递的可追踪性；明确状态能帮助用户识别通知授权失效等问题。

**Independent Test**: 模拟一次微信通道暂时失败和一次持续失败，验证重试、最终状态和用户可见的处理提示，即可独立验证该故事。

**Acceptance Scenarios**:

1. **Given** 微信通道暂时无法接收消息，**When** 首次发送失败，**Then** 系统记录失败原因并在有效提醒窗口内自动重试。
2. **Given** 提醒在重试后被微信通道接受，**When** 用户查看提醒记录，**Then** 该提醒显示为已发送且不再重试。
3. **Given** 微信授权失效或在有效窗口内持续发送失败，**When** 系统结束重试，**Then** 提醒显示为失败，并提示用户重新绑定或检查微信通知权限。

### Edge Cases

- 用户输入的下一次续费日期已经过去时，系统不接受直接启用提醒，并要求用户改为未来日期。
- 下一次续费日期临近，已经短于用户设置的提前提醒时间时，系统安排尽快提醒，而不是静默跳过本次续费。
- 按月或按年推算时目标月份没有对应日期（例如 1 月 31 日之后的一个月），下一次日期取目标月份的最后一个有效日期。
- 用户修改订阅时，已经成功发送的提醒记录保持不变；仅未来未发送的提醒按新设置更新。
- 用户停用、删除订阅或解除微信绑定后，尚未发送的提醒不得继续发送。
- 同一用户可以创建名称相同的订阅，但系统应提示可能重复，避免误录导致多条提醒。
- 用户所在时区变化时，未来提醒按用户当前选择的时区重新计算，并向用户展示变化后的时间。
- 金额或套餐名称未填写时，提醒仍可发送，但不得展示错误的金额或套餐信息。
- 微信通道延迟确认、重复回执或系统重复执行任务时，同一次续费的同一提醒时间不得产生重复消息。

## Requirements *(mandatory)*

### Scope

**In scope**:

- 用户手动创建、查看、编辑、停用、重新启用和删除自己的软件订阅记录。
- 根据用户录入的续费日期、计费周期和提醒设置安排提醒。
- 绑定并验证一个可接收消息的微信通知身份。
- 发送续费提醒，并记录提醒的处理状态。

**Out of scope**:

- 自动读取银行卡、应用商店、邮箱或第三方软件中的订阅和账单。
- 代表用户取消订阅、阻止扣款、发起退款或完成续费支付。
- 保证第三方软件实际扣款日期、金额与用户手动录入的信息一致。
- 多人共享订阅、费用分摊及企业订阅管理。

### Functional Requirements

- **FR-001**: 系统必须允许用户创建订阅记录；服务名称、下一次续费日期、是否自动续费、计费周期和时区为必填信息。
- **FR-002**: 系统必须允许用户选填套餐名称、预计续费金额、币种和备注；未填写的可选信息不得阻止提醒。
- **FR-003**: 系统必须验证下一次续费日期晚于当前时间、金额不为负数，并对缺失或无效字段给出可操作的错误提示。
- **FR-004**: 系统必须为每个启用中的自动续费订阅维护至少一个提前提醒时间，默认在续费日期前 3 天提醒，并允许用户修改提前天数和当天提醒时刻。
- **FR-005**: 系统必须在保存或修改订阅后，向用户展示下一次续费日期和下一次提醒时间；当本次续费已进入提醒窗口时，必须尽快安排提醒。
- **FR-006**: 系统必须允许用户绑定、验证、解除绑定微信通知身份，并清楚显示当前绑定及可接收通知状态。
- **FR-007**: 未完成有效微信绑定时，系统必须允许保存订阅，但必须明确提示提醒暂时无法发送，且不得将该提醒标记为已发送。
- **FR-008**: 微信提醒必须包含服务名称、预计续费日期和用户可识别的订阅标识；套餐名称、预计金额和币种仅在用户已填写时展示。
- **FR-009**: 系统必须确保同一订阅、同一次续费、同一个提醒时间最多产生一条成功发送的微信消息。
- **FR-010**: 系统必须允许用户查看订阅列表和单项详情，并展示状态、下一次续费日期、下一次提醒时间及最近一次提醒状态。
- **FR-011**: 用户必须能够编辑自己的订阅；影响提醒安排的修改必须取消旧的未发送安排，并以最新信息重新计算未来提醒。
- **FR-012**: 用户必须能够停用、重新启用和删除自己的订阅；停用或删除后不得继续发送尚未开始处理的提醒。
- **FR-013**: 对于启用中的周期性自动续费订阅，系统必须在当前续费日期过去后按计费周期推算下一次续费日期；遇到无对应日的月份时使用该月最后一个有效日期。
- **FR-014**: 系统必须记录每次提醒的订阅、目标续费日期、计划时间、实际处理时间以及待发送、已发送或失败状态。
- **FR-015**: 微信通道发生可恢复的临时失败时，系统必须在提醒仍有意义的时间窗口内自动重试；授权失效等不可恢复错误不得持续重试。
- **FR-016**: 最终发送失败时，系统必须在用户查看订阅或提醒记录时说明失败状态、可理解的原因和建议操作。
- **FR-017**: 系统必须按照用户选择的时区计算和展示续费与提醒时间；时区变化后，尚未发送的提醒必须按新时区重新计算。
- **FR-018**: 每名用户只能查看和操作自己的订阅、微信绑定信息及提醒记录。
- **FR-019**: 系统必须在创建疑似重复订阅时提示用户核对，但允许用户确认后继续保存，以支持同一服务的多个账号或套餐。

### Key Entities

- **User**: 使用订阅提醒服务的人，拥有时区偏好、微信通知绑定状态以及自己的订阅和提醒记录。
- **Subscription**: 用户手动维护的一项软件订阅，包含服务名称、套餐信息、预计金额、币种、自动续费状态、计费周期、下一次续费日期、状态和备注。
- **Reminder Setting**: 某项订阅的提醒规则，包含提前天数、当天提醒时刻和适用时区。
- **Notification Binding**: 用户与微信通知身份之间的授权关系，包含绑定状态、验证状态和失效状态。
- **Reminder Delivery**: 针对某项订阅某次续费的单次提醒记录，包含计划时间、处理时间、状态、失败原因和重试情况。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 至少 90% 的首次使用者能够在 2 分钟内完成一项订阅的录入，并确认下一次提醒时间。
- **SC-002**: 对于微信绑定有效且信息完整的订阅，至少 99% 的提醒在计划时间后的 10 分钟内被微信通知通道接受。
- **SC-003**: 在重复执行、延迟确认和自动重试场景中，至少 99.9% 的续费提醒不会向同一用户产生重复消息。
- **SC-004**: 在可用性测试中，至少 95% 的用户能从提醒消息中正确识别哪个服务将在何时续费，以及预计金额（如已录入）。
- **SC-005**: 100% 的停用或删除订阅在操作完成后不再产生新的微信提醒。
- **SC-006**: 至少 95% 的测试用户能够在 1 分钟内完成续费日期修改或订阅停用，并确认更新后的提醒状态。

## Assumptions

- 首版面向管理个人软件订阅的单一用户，不包含家庭或团队协作。
- 用户对手动录入信息的准确性负责；产品提供提醒，但不对第三方实际扣款负责。
- 每项订阅默认提前 3 天提醒，用户可以按需要修改提前天数和当天提醒时刻。
- 用户提供计费周期后，系统可以推算后续续费日期；用户取消订阅、价格变化或续费失败时，需要手动更新记录。
- 微信通知依赖用户完成必要授权，且第三方通知通道在提醒时可用。
- “已发送”表示消息已被微信通知通道接受，不保证用户已经阅读。
- 用户解除绑定后，其订阅数据仍保留，但所有微信提醒暂停，直到重新完成有效绑定。

## Dependencies

- 可用且符合微信平台规则的消息通知能力。
- 可识别当前用户并隔离个人数据的账号能力。
- 稳定、可信的当前时间与用户时区信息。
