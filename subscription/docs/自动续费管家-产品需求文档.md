# 自动续费管家 - 产品需求文档

> 产品代号：续费清单（暂定）  
> 文档版本：V1.0  
> 文档日期：2026-07-29  
> 目标平台：微信小程序  
> 文档状态：MVP 评审稿

## 1. 文档摘要

“续费清单”是一款帮助用户集中记录各类软件、会员和数字服务自动续费信息的小程序。产品不替用户扣款，也不承诺替用户取消订阅；它通过清晰的订阅台账、续费日历和分阶段提醒，让用户在下一次扣费前知道“什么服务、何时扣费、扣多少钱、去哪里关闭”。

首版重点不是做一个复杂的记账工具，而是建立最短可用闭环：**录入订阅 -> 获得提醒授权 -> 到期前提醒 -> 用户完成续费或取消 -> 更新状态**。

### 1.1 核心价值

- 防遗忘：降低因忘记取消试用、低频会员或年度套餐产生的非预期扣费。
- 看全貌：集中查看月度和年度订阅支出，识别重复、闲置和高成本服务。
- 可行动：在提醒中直接展示取消路径、备注和操作入口，缩短处理时间。
- 低负担：常用服务可从模板快速添加，周期和下次扣费日自动推算。

### 1.2 产品边界

- 产品记录的是用户自行提供的信息，不代表支付平台或服务商的实时账单。
- 产品发送的是提醒，不保证服务商不会提前扣款或调整价格。
- 产品不保存支付密码、银行卡号、身份证号等高敏感支付信息。
- 产品不代替用户取消订阅；取消动作仍需在原应用、应用商店或支付渠道完成。

## 2. 背景与机会

用户的数字订阅分散在 App Store、各类安卓应用商店、微信支付、支付宝、信用卡以及服务商官网。扣费周期可能是周、月、季、年或试用后转付费，取消路径也不一致。现有日历和记账产品能够记录日期或支出，但通常缺少订阅周期推算、取消路径、提醒确认和续费状态管理。

机会在于用一个足够轻量的工具，把“即将扣费”转化成一个明确、可处理的待办，而不是再做一套重型财务系统。

## 3. 产品目标与成功指标

### 3.1 阶段目标

MVP 上线后 8 周内验证三件事：用户是否愿意持续录入订阅、提醒是否能促成处理、订阅总览是否能带来复访。

### 3.2 北极星指标

**每周被用户确认处理的到期订阅数**，包括确认续费、已取消、暂停和延后处理。

### 3.3 核心指标

| 指标 | 定义 | MVP 参考目标 |
| --- | --- | --- |
| 首次录入完成率 | 新用户在首次访问 10 分钟内成功创建至少 1 条订阅 | >= 60% |
| 有效提醒覆盖率 | 未来 30 天内到期且已具备至少一次可发送提醒授权的订阅占比 | >= 70% |
| 提醒处理率 | 用户打开提醒后 72 小时内更新订阅状态的比例 | >= 35% |
| 4 周留存率 | 首次创建订阅后第 4 周仍有访问或处理行为的用户占比 | >= 20% |
| 数据完整率 | 同时具备金额、周期、下次扣费日的有效订阅占比 | >= 85% |

指标目标用于产品验证，不作为上线硬门槛；上线前应结合真实流量和触达能力重新校准。

## 4. 目标用户与典型场景

### 4.1 目标用户

- 订阅较多的数字消费者：同时使用影音、办公、云存储、AI、健身等服务。
- 容易忘记试用截止日的用户：经常开通首月优惠、免费试用或短期会员。
- 有预算意识的个人或家庭：希望知道每月固定支出，并定期清理低利用率订阅。
- 代家人管理会员的用户：需要备注实际使用人、付款渠道和取消方式。

### 4.2 核心场景

1. 用户开通 7 天免费试用，立即记录试用截止日，并设置提前 3 天和 1 天提醒。
2. 用户月底查看下月将扣费的全部会员，取消不再使用的服务。
3. 用户收到年度会员提醒，通过记录的取消路径进入原应用处理，并回到小程序标记“已取消”。
4. 用户查看月均订阅成本，发现两个功能重复的云盘服务，决定保留一个。

## 5. MVP 范围

### 5.1 本期必须实现

- 微信授权登录及云端数据同步。
- 订阅的新增、编辑、复制、归档和删除。
- 常用服务模板、分类、搜索和自定义服务名称。
- 周期、金额、币种、下次扣费日、试用状态、付款渠道和备注。
- 首页总览、即将到期列表、全部订阅列表和月历视图。
- 默认提醒规则与单条订阅自定义提醒。
- 小程序订阅消息授权、提醒发送结果记录和授权不足提示。
- 提醒后的“确认续费 / 已取消 / 稍后处理”闭环。
- 月均支出、年度预计支出和分类占比的基础统计。
- 数据导出、账号注销和隐私说明。

### 5.2 本期不做

- 自动读取微信、支付宝、银行卡或应用商店账单。
- 自动代扣、自动取消或退款申请。
- OCR 截图识别、邮件账单解析和 AI 自动分类。
- 家庭共享、多人协作和订阅费用分摊。
- 复杂预算、复式记账、发票和企业报销。
- 价格比价、优惠券导购或商业推荐位。

## 6. 信息架构

底部导航采用 3 个一级入口，减少小程序内的切换成本。

| 一级页面 | 主要内容 | 核心动作 |
| --- | --- | --- |
| 首页 | 本月预计支出、最近 7/30 天到期、待处理提醒、快捷添加 | 查看详情、处理提醒、新增订阅 |
| 订阅 | 全部订阅、分类筛选、搜索、状态筛选、月历 | 筛选、编辑、归档、查看日历 |
| 我的 | 默认提醒、通知授权、币种、数据导出、隐私与账号 | 管理偏好、补充授权、导出或注销 |

全局右下角保留明确的“新增订阅”主操作；详情页承担编辑、处理状态与查看取消方式。

## 7. 核心用户流程

### 7.1 首次使用

1. 用户进入小程序，看到简短价值说明和隐私提示。
2. 用户点击“添加第一条订阅”，可先录入再登录。
3. 用户选择常用服务模板或输入自定义名称。
4. 用户填写金额、周期和下次扣费日；系统自动展示预计提醒日期。
5. 保存前，产品在明确场景中请求订阅消息授权。
6. 保存成功后进入首页，并突出显示最近一次扣费。

### 7.2 到期处理

1. 定时任务筛选进入提醒窗口且具备发送条件的订阅。
2. 系统发送订阅消息，并记录发送结果。
3. 用户点击消息进入订阅详情，查看金额、扣费日、付款渠道和取消路径。
4. 用户选择“确认续费”“已取消”或“稍后处理”。
5. 确认续费后，系统按周期推算下一扣费日；已取消后停止后续提醒；稍后处理可选择当天晚些时候或次日再次提醒，但需满足可用授权条件。

## 8. 功能需求

### 8.1 登录与新手引导

- 支持微信快捷登录；未登录用户可体验录入流程，保存云端数据前完成授权登录。
- 首次进入只展示 1 个主动作，不强制用户先阅读多页引导。
- 首次保存时展示通知用途、预计发送日期和可随时关闭的说明，不用模糊文案诱导授权。
- 用户拒绝通知授权后仍可正常使用台账和日历，页面提供非阻塞式补充授权入口。

### 8.2 新增与编辑订阅

必填字段：服务名称、计费周期、下次扣费日。金额允许暂时未知，但未知金额不计入支出统计并显示“待补充”。

| 字段 | 规则 |
| --- | --- |
| 服务名称 | 1-30 个字符；支持模板选择和自定义输入 |
| 分类 | 影音、音乐、办公、云存储、AI 工具、阅读、游戏、健康、教育、生活服务、其他 |
| 金额与币种 | 金额 >= 0，最多 2 位小数；默认 CNY，可选常见币种 |
| 计费周期 | 周、月、季度、半年、年、自定义天数、一次性 |
| 下次扣费日 | 不早于当前日期；录入历史订阅时允许选择“已扣费，推算下一期” |
| 试用状态 | 非试用、试用中；试用中可单独记录试用截止日 |
| 付款渠道 | App Store、安卓应用商店、微信支付、支付宝、银行卡、官网、其他 |
| 自动续费 | 默认开启；关闭时作为普通到期待办，不再使用“自动扣费”文案 |
| 提醒规则 | 默认提前 7 天、3 天、1 天和当天，可按订阅调整 |
| 取消路径 | 自由文本或链接；模板可预填通用说明，必须提示用户自行核验 |
| 备注 | 最多 500 字，可记录账号尾号、家庭成员等非敏感信息 |

保存时校验重复项：若同一用户存在名称相同、金额相同且扣费日在前后 3 天内的活跃订阅，弹出重复提示，但允许继续保存。

### 8.3 首页总览

- 顶部展示“本月预计扣费”，旁边展示数据口径说明。
- 默认展示未来 30 天内的订阅，按扣费日升序排列；7 天内项目使用更高视觉优先级。
- 每条记录展示服务名称、金额、扣费日、剩余天数和提醒状态。
- 存在授权不足、日期异常或金额缺失时，在首页提供可处理的数据质量提示。
- 空状态直接提供常用模板和新增入口，不展示与任务无关的营销内容。

### 8.4 订阅列表与日历

- 支持按状态、分类、付款渠道和扣费月份筛选，支持服务名称搜索。
- 状态包括：试用中、正常、即将到期、待处理、已暂停、已取消、已归档。
- 列表支持按扣费日、金额和创建时间排序。
- 日历以扣费日显示订阅数量和当日预计金额；点击日期展开明细。
- 已取消和已归档默认不进入预计支出，可通过筛选查看历史记录。

### 8.5 提醒中心

提醒采用“用户默认规则 + 单条覆盖”的两层配置。默认建议为提前 7 天、3 天、1 天和当天 09:00；具体可用次数与发送方式受微信订阅消息能力和用户授权状态限制。

- 每次请求授权前明确说明对应提醒用途，不在无关页面反复弹出。
- 系统记录授权状态、计划发送时间、实际发送时间、发送结果和失败原因。
- 同一订阅同一提醒节点必须幂等，重复任务不得重复发送。
- 用户修改扣费日后，取消未发送的旧计划并重建提醒计划。
- 用户已取消、暂停或归档后，不再发送自动续费提醒。
- 当授权不足时，站内仍显示到期待办，并在用户主动操作时提示补充授权。
- 服务端每日执行补偿扫描，处理因任务延迟而遗漏但仍在有效窗口内的提醒。

> 平台约束：微信订阅消息通常需要用户主动授权，且一次性订阅的可发送次数受授权次数影响；长期订阅消息仅对特定公共服务领域开放。开发前必须根据实际小程序类目、模板和当期平台规则复核，不能把“永久免费持续提醒”作为未经验证的产品承诺。

### 8.6 到期处理与状态流转

| 当前状态 | 用户动作 | 结果 |
| --- | --- | --- |
| 试用中 / 正常 / 即将到期 | 确认续费 | 记录本次处理，并按周期推算下次扣费日 |
| 试用中 / 正常 / 即将到期 | 已取消 | 状态变为已取消，停止未来提醒，保留历史 |
| 即将到期 / 待处理 | 稍后处理 | 状态变为待处理，创建可用的再次提醒或站内待办 |
| 正常 / 待处理 | 暂停 | 状态变为已暂停，不推算新扣费日 |
| 已暂停 | 恢复 | 用户重新确认扣费日后恢复正常 |
| 任意非删除状态 | 归档 | 从默认视图隐藏，不计入支出预测 |

一次性项目完成后自动进入已归档；自定义周期按自然日递增。月、季度、半年、年周期按自然月推算：若目标月份不存在原日期，则取该月最后一天，并在下一周期尽可能恢复原始锚点日期。

### 8.7 统计

- 本月预计扣费：本自然月内所有活跃且金额已知的订阅金额之和。
- 月均支出：将周、季、半年、年等周期折算为月均，仅用于估算并标注“约”。
- 年度预计支出：基于当前价格和周期推算未来 12 个月，不包含已取消、暂停、归档和金额未知项目。
- 分类占比：按折算后的月均金额计算。
- 多币种不做隐式实时汇率换算；按币种分别汇总。后续如接入汇率，必须显示汇率来源和更新时间。

### 8.8 设置、数据与账号

- 用户可设置默认提醒节点、默认提醒时间、默认币种和每周摘要开关。
- 支持导出 CSV，字段包含服务、分类、金额、币种、周期、扣费日、状态、付款渠道和备注。
- 提供账号注销入口。注销前说明影响并二次确认；进入冷静期或按产品隐私政策执行删除。
- 用户可单独清空业务数据，不等同于注销账号。
- 隐私政策中明确数据用途、存储期限、第三方服务、用户权利和联系方式。

## 9. 关键业务规则

### 9.1 状态计算优先级

```text
已归档 / 已取消 / 已暂停（人工状态优先）
    -> 试用截止日在未来：试用中
    -> 扣费日已过且未处理：待处理
    -> 距扣费日 <= 用户定义的最近提醒窗口：即将到期
    -> 其他：正常
```

服务端保存基础状态和关键日期，展示状态按统一规则计算，避免多个端各自判断产生不一致。

### 9.2 日期与时区

- 默认使用用户设置的时区，首版默认 Asia/Shanghai。
- 扣费日按“当地自然日”存储，提醒计划使用带时区的时间戳。
- 用户跨时区时不自动改变扣费自然日；可在设置中主动切换时区并预览影响。
- 定时任务、补偿任务和客户端展示使用同一套时区规则。

### 9.3 金额口径

- 金额采用十进制字符串或最小货币单位整数存储，禁止使用浮点数直接计算。
- 金额为 0 时标记为免费或赠送，不与“金额未知”混淆。
- 修改价格只影响未来预测；历史处理记录保留当时金额快照。

## 10. 数据模型建议

| 实体 | 关键字段 |
| --- | --- |
| User | id、openid/unionid、timezone、defaultCurrency、reminderDefaults、createdAt、deletedAt |
| ServiceTemplate | id、name、category、icon、commonChannels、cancelGuide、guideVerifiedAt、status |
| Subscription | id、userId、serviceName、templateId、category、amountMinor、currency、cycleType、cycleValue、anchorDay、nextBillingDate、trialEndDate、channel、autoRenew、status、cancelGuide、note、version |
| ReminderPlan | id、subscriptionId、offsetDays、sendAt、channel、authorizationRef、status、dedupeKey、sentAt、failureCode |
| BillingAction | id、subscriptionId、actionType、billingDate、amountSnapshot、nextBillingDateSnapshot、createdAt |
| ConsentLog | id、userId、consentType、templateId、result、scene、createdAt |

所有修改接口建议携带 `version` 做乐观锁；提醒任务使用稳定的 `dedupeKey`，例如 `subscriptionId + billingDate + offsetDays + channel`。

## 11. 异常与边界场景

- 用户录入 31 日月付：2 月按月末处理，3 月尽可能恢复到 31 日。
- 用户将扣费日改到今天之前：要求选择“已扣费并推算下一期”或“保留为待处理”。
- 用户修改周期或金额：未发送提醒重建，历史处理记录不改写。
- 用户删除订阅：先进入可恢复的回收状态，服务端异步清理关联提醒；发送任务执行前再次校验状态。
- 微信消息发送失败：记录失败码，不无限重试；可重试错误按退避策略处理，永久错误转站内提示。
- 用户拒绝或关闭通知：核心记录功能仍可用，不循环弹窗。
- 同账号多设备同时编辑：后提交方收到版本冲突提示并刷新数据。
- 服务商提前扣费或价格变化：允许用户快速修正，并在详情显示“信息由用户维护”。

## 12. 非功能需求

### 12.1 性能与可用性

- 首页首屏接口 P95 响应时间 <= 800ms（不含弱网传输），列表分页默认 20 条。
- 新增订阅从打开表单到完成保存，常用模板路径目标不超过 45 秒。
- 提醒计划创建、更新和取消必须可重试且幂等。
- 服务端关键任务具备运行监控、失败告警和人工补偿入口。

### 12.2 安全与隐私

- 客户端与服务端全程 HTTPS；敏感标识最小化存储并限制访问权限。
- 日志不得记录完整 openid、备注全文或可能包含账号信息的取消链接参数。
- 取消路径中的外部链接需校验协议和域名风险，并在跳转前提示将离开小程序。
- 后台操作保留审计日志；生产数据访问遵循最小权限。
- 数据导出需二次确认，导出链接短时有效且仅当前用户可访问。

### 12.3 可访问性与体验

- 状态不能只依赖颜色表达，需同时使用文字或图标。
- 关键按钮触控区域不小于 44px，支持系统字体放大后的正常换行。
- 金额、日期和周期在所有页面使用统一格式。
- 危险操作使用明确对象名称，例如“删除 Netflix 订阅”，避免含糊确认框。

## 13. 埋点与分析

| 事件 | 关键属性 | 用途 |
| --- | --- | --- |
| onboarding_view | source | 识别入口质量 |
| subscription_create_started | templateId、source | 评估模板和入口 |
| subscription_created | category、cycleType、hasAmount、hasReminder | 计算首次录入和完整率 |
| reminder_permission_result | scene、templateId、result | 优化授权时机 |
| reminder_send_result | offsetDays、result、failureCode | 监控触达质量 |
| reminder_opened | offsetDays、subscriptionStatus | 计算打开和处理漏斗 |
| billing_action_completed | actionType、source | 计算核心处理指标 |
| subscription_exported | recordCount | 评估数据可携带需求 |

埋点不得上传订阅备注、完整服务账号或其他非分析必需的个人内容。

## 14. 版本规划

### 14.1 MVP（建议 4-6 周）

- 第 1 周：产品细化、原型、消息模板与类目能力核验、数据模型评审。
- 第 2-3 周：登录、订阅 CRUD、模板、首页与列表、状态规则。
- 第 3-4 周：提醒授权、任务调度、消息发送、处理闭环、统计。
- 第 5 周：导出、注销、隐私合规、埋点、后台监控和全链路测试。
- 第 6 周：灰度、问题修复、提醒到达率与处理漏斗校准。

### 14.2 后续方向

- V1.1：每周订阅摘要、桌面组件适配、批量编辑、更多服务模板。
- V1.2：经用户明确授权的截图 OCR 辅助录入，识别结果必须由用户确认后保存。
- V2.0：家庭共享、费用分摊、价格变动记录、跨端 Web 管理。
- 商业化探索：高级统计、多设备/家庭空间、个性化主题；不以出售用户订阅明细为商业模式。

## 15. MVP 验收标准

1. 用户可在常用模板路径下，于 45 秒内完成一条月付订阅的创建。
2. 新建、编辑、取消、暂停、恢复和归档后，列表、首页统计和提醒计划保持一致。
3. 月末锚点、闰年、跨年和自定义周期的下一扣费日通过自动化测试。
4. 同一提醒任务重复执行不会产生重复消息。
5. 用户拒绝通知授权后仍能完成所有台账操作，且不会在一次会话内重复打扰。
6. 已取消、暂停、归档或删除的订阅不会继续发送提醒。
7. 提醒消息点击后可准确进入对应详情；用户处理后可看到下一扣费日或停止提醒状态。
8. 金额未知、金额为 0 和多币种场景的统计口径与文案正确。
9. CSV 导出内容与当前用户可见数据一致，其他用户无法访问。
10. 注销或数据清理流程可验证，相关提醒任务和业务数据按政策处理。

## 16. 上线前待确认事项

- 小程序主体、服务类目、隐私指引和订阅消息模板是否满足平台审核要求。
- 一次性订阅消息的授权次数、模板字段、跳转路径和发送频率限制。
- 服务端技术方案、云开发或自建后端、数据保留周期及告警渠道。
- 常用服务模板中的品牌名称、图标和取消指引是否涉及授权及维护责任。
- 冷启动模板清单、灰度用户来源、核心指标基线与复盘节奏。
- 是否需要在 MVP 支持海外币种；若支持，确认“不自动换汇”的产品表达。

## 17. 产品原则

- **先提醒，再分析**：到期处理闭环优先于复杂图表。
- **可用但不打扰**：拒绝通知不影响核心功能，授权请求只出现在有明确价值的场景。
- **信息可核验**：所有模板和取消指引均标记更新时间，用户对最终信息负责。
- **数据属于用户**：支持导出、删除和注销，不用订阅明细做隐蔽画像。
- **不夸大能力**：不承诺自动取消、不保证持续推送、不把估算金额描述成真实账单。
