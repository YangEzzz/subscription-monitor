# 续订清单 - 会员权限逻辑框架

> 版本：V0.1  
> 当前阶段：本地交互原型

## 1. 业务规则

- 免费用户最多保存 5 条订阅。
- 会员用户可无限新增订阅。
- 编辑现有订阅不占用新额度。
- 复制订阅等同于新增，需要经过额度校验。
- 会员恢复为免费版后，已有订阅不删除；数量达到或超过 5 条时禁止继续新增。
- 删除订阅后释放一个免费额度。

## 2. 当前本地数据

会员状态保存在本地设置中：

```js
membership: {
  status: 'free', // free | active
  plan: '免费版',
  startedAt: null
}
```

当前使用 `uni.setStorageSync` 持久化，不包含真实订单、支付和服务端校验。

## 3. 权限校验点

```text
点击新增/日历新增
    -> 会员：进入新增页
    -> 免费且订阅数 < 5：进入新增页
    -> 免费且订阅数 >= 5：提示额度已用完 -> 会员中心

保存新订阅
    -> 再次执行相同校验，防止绕过入口

复制订阅
    -> 按新增订阅执行相同校验

编辑订阅
    -> 不校验额度，始终允许编辑已有数据
```

## 4. 会员页面框架

- 展示免费版与会员版权益对比。
- 展示当前方案和已使用额度。
- 免费用户可执行“本地模拟开通会员”。
- 会员用户可执行“恢复为免费版”，用于调试降级逻辑。
- 当前页面明确提示不会产生真实扣款。

## 5. 接入后端后的替换边界

正式版本不能信任客户端会员状态，需要由服务端返回权益：

```js
entitlement: {
  plan: 'free' | 'pro',
  status: 'active' | 'expired' | 'refunded',
  subscriptionLimit: 5 | null,
  effectiveAt: 0,
  expiresAt: 0,
  source: 'wechat'
}
```

- 创建和复制接口必须在服务端事务内再次校验额度。
- 支付成功以服务端支付回调为准，不能以客户端支付结果直接开通。
- 退款、到期和订单关闭后由服务端更新权益。
- 客户端本地状态只用于缓存展示，不作为最终授权依据。
- 需要记录订单号、商品、金额、支付状态、权益生效时间和退款状态。

## 6. 后续待确认

- 会员是按月、按年还是一次性买断。
- 定价、试用和优惠策略。
- 会员除无限订阅外是否包含更多提醒、导出或统计权益。
- 会员到期后，超过 5 条的已有订阅是否继续提醒。建议保留查看与提醒，只限制新增。
- 删除或归档是否释放免费额度。当前规则只有删除释放，归档仍占额度。
