# 会员功能设计

> 2026-10-01 实施调整：用户选择先模拟支付，之后接真实支付。当前实现和开启步骤见 [模拟会员支付](../../deploy/模拟会员支付.md)。原真实支付方案保留为后续设计。

日期：2026-10-01。状态：¥29.90 永久会员的模拟支付已实现，真实微信支付待后续接入。以下原方案描述真实支付目标，历史代码描述为设计时的基线；当前实现以部署说明为准。

## 1. 当前代码与设计范围

现有服务端免费额度为 5 条，会员状态为 free/active，会员可无限新增。会员绑定微信登录后的稳定 userId；相同 AppID + OpenID 始终对应同一账号。

当前 Membership 只有 startedAt，没有 expiresAt；GET /membership 只提供查询。没有商品、订单、支付回调、退款和到期处理。旧《会员权限逻辑框架》中的本地模拟开通内容已过时，不能作为当前实现依据。

代码依据：backend/src/auth/auth.service.ts、backend/src/subscriptions/subscriptions.service.ts、backend/prisma/schema.prisma、subscription/components/subscription/MembershipView.vue。

本设计先定义业务和交互，再实现服务端权益，最后接购买流程。首发售价 ¥29.90，服务端以整数分保存为 2990；前端读取服务端商品价格，不在前端写死。

## 2. 权益方案

| 能力 | 免费版 | 会员版 |
| --- | --- | --- |
| 未删除订阅数量 | 最多 5 条 | 不限数量 |
| 查看、编辑、确认续费、删除已有订阅 | 支持 | 支持 |
| 微信提醒 | 授权后支持，沿用现有规则 | 相同规则 |
| 云端账号数据 | 支持 | 支持 |
| 现有支出统计及 CSV 导出 | 保留 | 保留 |

第一版不收回用户已经拥有的提醒、统计或导出功能。不宣传尚未实现的短信、邮件、家庭账号或自动读取账单。

数量规则沿用现状：所有未删除且非演示的记录占额度，包括归档、暂停和已取消记录；删除释放额度，恢复重新占额度。创建、复制、恢复均在服务端检查，编辑和确认续费不占新额度。

退款或撤销会员后若已有 12 条，保留这 12 条的查看、编辑、删除及符合原规则的提醒；不能新增、复制或恢复，直到数量低于 5 或重新开通会员。显示“当前 12 条，免费额度 5 条；已有数据保留”。

## 3. 已确认的商品与生效规则

只有一个永久会员商品，一次支付，无自动扣费、到期续费、月卡或年卡。售价 ¥29.90（CNY 2990 分），由服务端配置，前端读取真实售价。

- 首次开通：以服务端确认的支付成功订单为依据，在权益可靠落库后生效。
- 永久会员明确使用 lifetime 标志；没有到期时间，不设置 2099 年之类的虚假日期。
- 会员绑定微信账号。更换设备、清缓存、重新登录均保留权益。
- 已是永久会员时不允许再次购买；展示“已开通永久会员”及订单记录。
- 同一用户重复点击复用未支付订单。若出现不同订单同时付款，第一单正常开通，后续已付款订单进入重复购买处理并发起退款；记录需可补偿。
- 退款成功仅撤销该订单赋予的权益。账号若还有其他有效赠送或付费权益，继续保留对应会员状态。

## 4. 小程序页面

### 会员中心

沿用现有绿色和账簿样式，不新增视觉主题。页面顺序：账号状态与用量、权益对比、永久会员售价、一次购买按钮、订单记录入口、一次付款无自动续费的说明。

- 免费：显示“免费版 · 已使用 3 / 5 条”，支付启用后按钮“¥29.90 · 开通永久会员”。
- 永久会员：显示“永久会员 · 订阅数量不限”，开通时间及订单入口；购买按钮替换为已开通状态。
- 退款后无其他有效权益：恢复免费额度，已有数据保留，不显示到期或续费入口。
- 加载失败：保留已读取状态并说明可能过期，提供重试；商品信息未读取成功时不允许下单。
- 支付未启用：按后端 availability 返回具体说明，不能显示可用的购买按钮或模拟成功。

首页新增达到额度时，在现有提示中提供会员中心入口；正常首页不增加反复弹窗。会员中心始终展示真实后端权益。

### 支付结果与订单记录

用户点击开通后，后端生成永久会员订单，小程序拉起平台收银台。客户端返回成功或取消后，向后端查询真实订单状态。

- 已支付且权益已落库：展示“永久会员已开通”，刷新账号权益和会员额度。
- 正在确认：展示“正在确认支付结果”，短时轮询后提供“重新查询”；不引导重复购买。
- 用户取消：回到会员中心；取消收银台不等于已关闭订单，仍以服务端查单为准。
- 网络失败：保留订单号，可稍后在订单列表继续查询。
- 订单已关闭：显示已关闭，可重新创建订单。

订单列表展示商品、金额、创建时间、状态和订单号。详情展示开通时间、永久权益和退款进度。金额未知或服务端错误时不能使用假价格。

## 5. 服务端数据

建议拆分：

| 数据 | 作用与关键字段 |
| --- | --- |
| MembershipProduct | 商品 id、永久类型、价格（整数分）、币种、上下架、版本 |
| MembershipOrder | userId、商户订单号、商品名称/价格/永久权益快照、支付渠道、渠道订单号、支付状态、支付成功时间 |
| MembershipGrant | 来源订单或管理员操作、生效时间、永久标志、撤销时间；sourceOrderId 唯一，防止重复开通 |
| Membership | 账号当前权益投影：有效状态、startedAt、永久标志、更新时间 |
| MembershipRefund | 订单、退款号、退款金额、退款状态、完成时间 |
| MembershipAudit | 开通、撤销、退款和补单记录，包含操作者、原因、前后状态及来源编号 |

支付状态、退款状态、权益状态分别保存，不用一个 active 字段表达所有状态。会员查询返回 free/active 与 lifetime 标志，权益发放可标记 pending/applied；成功付款但权益暂未发放时要能恢复。

订单金额与权益类型从服务端商品读取，客户端只能提交 productId 和幂等请求号。修改商品价格不能影响已有订单。

现有 active 会员记录需在迁移前确认来源和期限，不能擅自改为付费订单或永久会员；新字段可先兼容旧数据，再由管理命令按实际情况补齐。

## 6. API 草案

| 方法与路径 | 用途 |
| --- | --- |
| GET /api/v1/membership | 当前权益、永久标志、额度、购买可用性及原因 |
| GET /api/v1/membership/products | 当前可售商品与服务端价格 |
| POST /api/v1/membership/orders | 创建本人订单，携带商品 ID 和幂等请求号 |
| GET /api/v1/membership/orders | 本人订单分页列表 |
| GET /api/v1/membership/orders/:id | 本人订单详情，必要时服务端查单补偿 |
| POST /api/v1/membership/orders/:id/pay | 获取有效订单支付参数，拒绝已支付、关闭或已失效订单 |
| POST /api/v1/payments/wechat/notify | 平台通知入口，按所选渠道验证签名及金额，不使用用户登录凭证 |
| POST /api/v1/payments/wechat/refund-notify | 退款通知入口，按渠道验证并更新退款与权益 |

支付通知对外开放接收不等于免验证。会员 API 使用微信登录身份，订单读写必须检查归属。

## 7. 支付一致性和退款

支付渠道需依据小程序实际支付能力选择；不能预先假定会员类商品都能使用普通 JSAPI 支付。权益与订单模块保持独立，通过渠道适配层接入合适接口。

确认支付时校验渠道签名、商户/应用、订单号、币种及实付金额；验签或金额不符不发权益。前端支付结果仅触发查询，不能直接开通。

同一订单支付通知与主动查单共用一个幂等结算函数。数据库事务中锁定订单及账号，记录支付成功、插入唯一权益凭证、更新账号权益；重复请求返回同一结果。通知接收后先可靠记录再确认，失败任务可重试补偿。

免费额度也应按账号加锁后在同一事务内计数并创建/恢复；当前普通事务没有明确串行计数保障，并发新增可能超过 5 条。

退款第一版建议仅由管理员处理整单退款，不做部分退款；退款处理中不提前撤销权益。渠道确认成功后，仅撤销对应订单的权益凭证，重算剩余有效购买权益；不能简单把整个账号改为免费。永久权益按订单撤销，不涉及按剩余天数折算。退款政策与具体计算规则需在开放购买前确定并展示。

## 8. 后台与手动开通

现有本地 HTML 可增加只读会员和订单列表：用户 ID、当前会员状态、是否永久、开通时间、来源、订阅用量，以及订单金额/状态。支持按账号搜索、状态筛选和订单详情。

当前 HTML 查询接口按用户要求无鉴权。涉及开通、撤销或退款的写操作不挂到这个只读接口：人工补偿通过服务器管理命令执行，输入 userId、原因并记录审计；后续采用有管理员身份验证的独立操作接口。首期正式开通走微信支付。

手动开通属于赠送/补偿，不伪造已支付订单。命令需有操作幂等号，重复执行不能重复发放权益。撤销手动权益不撤销用户其他订单权益。

## 9. 当前支付能力与开通准备

用户确认尚未开通微信支付商户号或小程序虚拟支付。设计可完成，生产购买入口保持不可用，直到对应支付能力配置和真实联调通过。

本商品只解锁软件功能，支付渠道优先核实小程序虚拟支付的“道具直购”能力是否适用。不要把永久会员接成周期性自动续费商品。最终渠道以该小程序后台实际开放能力和官方文档为准，不预设个人主体、终端能力或手续费。

准备信息包括：小程序主体类型、服务类目、支付后台实际可开通能力、正式商品及环境配置、回调 URL（https://subscription.yangezzz.top 下的独立支付路径）。如果采用虚拟支付，应使用对应的应用/商品/签名配置和接口；只有确定普通小程序支付适用时才使用商户号、API v3 等配置。

所有支付密钥仅放服务器私有环境配置，不填写到本地 HTML 或小程序源码，不提交 Git。设置完成后用渠道测试环境验证订单通知、主动查单、幂等发放和退款，再开放正式购买按钮。

用户侧未开通支付时显示“永久会员 ¥29.90 · 购买暂未开放”，已有永久会员仍正常显示权益。后端配置返回 purchaseAvailable=false 及原因，并拒绝创建可支付订单，不能模拟付款成功。

## 10. 实施与验收

后续真实支付交付目标包含完整微信支付闭环：

1. 售价已确认 ¥29.90。核实小程序主体及适用支付能力，完成商户或虚拟支付配置。
2. 数据迁移、永久权益判断、额度串行校验、单一永久商品和幂等订单。
3. 接入实际支付渠道、通知验证及主动查单、重复购买退款、任务补偿与订单退款。
4. 会员中心、购买结果、订单列表及后台只读会员/订单查询；部署配置和端到端验证。

必须验证：相同微信账号跨设备权益一致；4 条并发新增不能超过免费额度；创建/复制/恢复均受限；永久会员没有到期或续费入口；重复通知只开通一次；重复下单复用已有订单；多笔成功付款有退款补偿；支付金额不符不发权益；掉线及取消后正确查单；退款保留其他有效权益；旧会员迁移不丢数据。
