# 订阅 Excel 导出验证

2026-10-26：导出由 `pages/subscription/subscription-export.js` 统一生成 OOXML `.xlsx`，使用 `fflate` 0.8.2 压缩包内容，不依赖完整电子表格 SDK。客户端直接生成，不经过后端或第三方转换服务。

“我的 → 导出订阅数据 → 导出表格”会包含所有未删除订阅。H5 下载带日期的文件；微信覆盖复用应用自己的 `续订清单.xlsx`，打开文档并启用右上角菜单。预览失败时才询问是否打开文件发送界面，用户取消不作为错误；代码不自动选择联系人或发送。

金额为数字单元格，采用两位小数格式，币种独立成列；缺失金额留空，免费金额为数字 0。名称、套餐、日期和备注等使用显式文本类型，保留中文、前导零、逗号、引号和换行，避免公式内容被执行。输出有固定表头、列宽、自动筛选和冻结首行。不输出回收站，不更改订阅。

验证结果：

- 前端 85 项测试通过，包括文件格式、文字转义、零/未知金额、回收站排除、写入失败、预览失败后确认分享、取消分享、分享失败、接口不可用以及重复点击/取消确认。
- H5 和微信小程序生产构建通过；实际微信开发目录也已重建。
- 浏览器交互回归实际点击导出并收到 `.xlsx` 下载，样例保存在忽略目录 `.preview/export-ui-verified.xlsx`。独立使用 Python ZIP/XML 解析全部 6 个包内容，确认 5 行、4 个金额数字单元格、无公式单元格。
- 微信开发者工具已加载导出模块，使用上述本机内存测试会话的样例文件进行真实文件写入和 `wx.openDocument({fileType:'xlsx',showMenu:true})` 调用，成功回调为 opened。未导出真实账号数据，也未执行联系人发送。样例临时文件检查后清理。
- 手机端文档菜单、发送和保存路径仍需扫码预览核对，开发者工具成功不等于所有手机系统行为已验证。

本次安装依赖时 npm 穿透了本机项目中的 `@dcloudio`/`@vue` 全局编译器目录链接，并清理了其中的文件。已使用本机更新日志中的原下载地址获取同版本 `5.26.2026091411.1611` 安装包，核对包版本及构建哈希，仅恢复缺失文件，并恢复原有编译依赖链接。后续两端构建通过。此类带全局目录链接的 HBuilderX 项目应避免直接在这些链接存在时运行会清理 extraneous 包的安装命令，可在隔离目录安装依赖后复制项目所需包，防止再次影响编译器。
