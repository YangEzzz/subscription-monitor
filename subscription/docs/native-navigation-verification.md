# 微信小程序系统返回

原先所有视图都在 pages/subscription/index 内切换，微信的原生页面栈始终只有一层，系统返回会退出小程序。现在内部视图通过同一路径的原生 navigateTo 创建页面层级，navigationToken 仅引用进程内的导航上下文，不包含订阅或表单内容。

native-navigation.js 为各页面保留独立的视图、选择、表单和滚动状态；账号数据使用共享响应式状态，使详情读取、保存和删除结果同步到上一页。微信显示上一原生页时恢复该页的导航上下文。编辑保存后关闭编辑层，新增保存后在当前层显示详情；切换主标签和删除后返回根页。已销毁页面上的迟到保存不会重新打开详情。

微信不支持 uni-app onBackPress；原生侧滑也不能依赖离开询问拦截。保留自绘返回的未保存确认，并调用可用的微信返回询问接口。侧滑离开时，草稿按账号与编辑记录缓存在内存，再次进入同一记录时恢复；保存、显式放弃和账号切换会清除草稿。H5 保留原有视图导航。

验证覆盖原生页面栈模拟、嵌套返回、底层视图保持、共享账号数据更新、导航失败与重复点击、草稿恢复和账号隔离，并用实际详情与编辑方法验证保存后的栈深度、侧滑期间迟到的保存响应。微信小程序与 H5 构建已通过。

真机仍需重新编译并检查：列表进入详情后侧滑返回列表；详情进入编辑后侧滑返回详情；再次进入编辑恢复未保存内容；关于、提醒设置与会员页侧滑返回「我的」。首页为根页，系统返回仍按微信默认行为退出。

新增入口没有等待动画完成的定时器：按钮点击同步分发 create 事件。内部原生页面在 data 初始化阶段直接使用待打开的目标上下文，避免先创建首页组件再切换表单；对应回归测试在 onLoad 前验证初始视图、表单和返回栈。微信配置开启 lazyCodeLoading=requiredComponents，减少无关组件的提前注入。真实点击到首帧的时间仍需真机测量。

新增/编辑改为独立的 editor 原生页，避免重复打开包含首页、统计、会员、设置等组件的 index 页面。editor 仅声明表单、保存后详情、详情加载状态、共享保存栏及接口错误状态。保存栏由 SubscriptionSaveBar 统一维护，并放在两个入口的滚动容器之外。仅通过编译产物和导航测试验证结构及行为，不将其等同于已经测得真机延迟。

已完整重建实际开发目录 unpackage/dist/dev/mp-weixin，并核对 editor.js、路由注册和按需加载配置。该目录 index 页面直接声明 17 个组件，editor 页面直接声明 5 个；75 项测试和浏览器滚动/保存/返回回归通过。此组件数量对比不代表已经测得相同幅度的耗时改善。

## 模拟器新增耗时实测

当前测量平台为 devtools，开发者工具 2.02.2608060、基础库 3.17.2。通过本地微信自动化调用实际 openForm，记录进入导航方法、wx.navigateTo 调用、首次观察到 editor 原生页、表单数据发送和 Vue/native ready；观察轮询间隔为 10ms，存在调度误差。未保存任何测试订阅。

三次正常测量中，新增处理函数返回耗时为 1–4ms，首次观察到页面为 1272–1867ms，页面 ready 为 1590–2111ms。另一次紧接返回后的试验未在 10 秒内达到 ready，不用于稳定时延结论。此数据仅代表模拟器，不是真机耗时。

关闭 compileHotReLoad 后的 ready 为 1674ms，没有显示出明显改善，已恢复原 project.private.config.json。GPU 设置原本已开启。模拟器的 wx.preloadWebview 回调明确返回 not support。当前不能宣称模拟器延迟已消除，也不能据此推断真机表现。

## 新增页首帧与可选预热

用户最终选择保留蓝紫渐变，editor 使用 navigationStyle=custom，删除占位内容和原生标题同步，恢复共享 PageHeader。PageHeader 和状态栏位于 shell，首次只挂载轻量顶部，原生 onReady 后再挂载表单/详情；editorContentReady 是本页独立状态，不共享到账号数据。此顺序不含固定延时，也不能保证与原生栏相同的首帧时机。

共享表单、详情和详情加载组件的 showHeader 默认 true，editor 显式 false，避免重复顶部栏。shell 共用 page-atmosphere 渐变，内容背景透明，防止顶部与内容之间重绘渐变产生断层。shell 使用 100vh 的 flex 纵向布局，顶部与保存栏在滚动容器之外。

原生页 onReady 后尝试 wx.preloadWebview 预热下一页；不支持、接口缺失或抛错时静默降级，不阻断导航，明确不支持的运行环境不再重复调用。该调用不能证明真机耗时改善，需手机重新预览验证。

当前 78 项导航与业务测试、H5 与微信小程序构建通过。微信模拟器确认单一自绘顶部、完整表单和固定保存栏；滚动前后顶部均位于 y=47–97，滚动区 y=97–844。截图核对滚动后的保存栏仍在底部，自绘返回可关闭未修改表单并回到首页。编译产物使用 custom 导航及 6 个直接组件，首屏占位已删除。真机初始显示耗时仍不能由构建或模拟器结果推断。
