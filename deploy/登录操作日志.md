# 注册与登录操作日志

首次微信登录成功且实际新建 app_users 行，记录 register（注册）；已存在账号成功换取登录令牌，记录 login（登录）。普通携带有效令牌的业务请求不算再次登录，不逐请求写日志。现有账号首次使用新版本也记 login，不补造历史注册事件。被手动删除的账号重新登录新建记录时，会产生新的注册事件。

记录保存在 auth_events：用户 ID、动作、AppID、UTC 时间、客户端 IP、直连 IP、请求编号。不记录 OpenID、登录 code、会话密钥、令牌或 AppSecret。客户端 IP 沿用 TRUSTED_PROXY_CIDRS 信任规则；代理配置未修复时可能仍是网关地址。直连 IP 保留原 socket 地址用于排查。

账号写入和日志在同一数据库事务提交。日志写入失败则整个登录失败，不返回成功令牌，防止出现无来源记录的新账号；客户端可重试。并发首次登录只将真正创建用户行的操作记为注册。日志按账号外键级联删除；当前不自动清理历史日志，需根据实际增长和保留需求制定清理周期。

只读查询沿用已有管理接口访问限制，不增加公开业务接口：

- `/data?section=authEvents&page=1`
- `/data?section=authEvents&page=1&search=wx_用户ID`

每页 20 条，按时间倒序。现有本地 Vite 后台代理路径为 `/api/data?section=authEvents&page=1`。管理后台“操作日志”菜单支持搜索、分页和详情；用户详情的“查看操作日志”可筛选对应用户。

部署必须先在服务器运行 `pnpm db:deploy`，应用 20261024000000_auth_events 迁移，再部署新版 API。这里只修改源码，没有连接或修改线上数据库；已有 13 个账号不改动，不补造来源信息。迁移前不要直接启动新版 API，否则登录会因缺表失败。

验证：TypeScript 检查、Prisma schema 校验、后端 13 个测试套件共 75 项测试通过（包含并发首登、历史账号登录、失败登录、日志写入失败）。本机 PGlite 验证进程提前退出，未完成迁移实际执行及 SQL 事务回滚的数据库集成验证；尚未连接生产数据库。
