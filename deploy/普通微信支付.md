# 普通微信支付：永久会员

当前接入直连商户 APIv3 小程序支付，商品是 ¥29.90 永久会员，一次购买，不自动续费。是否获准销售该商品以微信对主体、类目和商户产品的审核为准。代码默认关闭，不会自动连接商户、部署或发起真实交易。

## 商户准备

在微信支付商户平台开通小程序支付，绑定本项目小程序 AppID。准备商户号、商户 API 证书序列号、对应的 `apiclient_key.pem` 私钥、32 字节 APIv3 密钥，以及微信支付公钥 ID 与公钥 PEM。本实现采用微信支付公钥模式，不自动下载或轮换平台证书；公钥轮换时同步更新文件和 ID 并重启服务。

配置只放在 `backend/.env` 或 `deploy/.env.production`，不要放在小程序、后台 `VITE_` 环境变量或 Git 中：

```dotenv
WECHAT_PAY_ENABLED=true
MEMBERSHIP_SIMULATION_ENABLED=false
WECHAT_PAY_MCH_ID=你的商户号
WECHAT_PAY_SERIAL_NO=商户API证书序列号
WECHAT_PAY_PRIVATE_KEY_PATH=/run/wechat-pay/apiclient_key.pem
WECHAT_PAY_API_V3_KEY=你的32字节APIv3密钥
WECHAT_PAY_PUBLIC_KEY_ID=PUB_KEY_ID_你的微信支付公钥ID
WECHAT_PAY_PUBLIC_KEY_PATH=/run/wechat-pay/wechatpay_public_key.pem
WECHAT_PAY_NOTIFY_URL=https://subscription.yangezzz.top/api/v1/membership/wechat/notify
```

现有 `WECHAT_APP_ID` 必须是已绑定商户号的小程序 AppID。`WECHAT_APP_SECRET` 继续用于登录、获取付款人的 OpenID；客户端不能指定其他人的 OpenID。启用但缺少参数或密钥文件时启动失败，不回退到模拟支付。

## 部署

将私钥和微信支付公钥放到服务器 `deploy/secrets/wechat-pay/`（已被 Git 忽略），只允许必要用户读取。容器运行用户为 node（UID 1000），文件须对该用户可读。目录通过可选 Compose 覆盖文件只读挂载。

在已配置真实 PostgreSQL 和支付参数的服务器运行：

```bash
docker compose -f compose.yaml -f deploy/compose.wechat-pay.yaml --env-file deploy/.env.production up -d --build api
docker compose -f compose.yaml -f deploy/compose.wechat-pay.yaml --env-file deploy/.env.production logs --tail=80 migrate api
```

Compose 的 migrate 服务先应用新增的 `membership_orders.transaction_id` 列和唯一索引；不删除已有订单或权益。普通非容器开发填写本机绝对文件路径，不需要 Compose 挂载。

支付通知必须经 HTTPS 公开转发至主业务端口 3001，不能放在带 Origin 限制的 `/admin/` 下，不要求用户 Bearer 令牌；它通过微信支付签名认证。Nginx 不应改写 JSON 通知报文或将该路径转成 HTML。主业务 API 原有 `/` 代理通常已覆盖此路径。

## 接口与确认规则

| 接口 | 行为 |
| --- | --- |
| POST /api/v1/membership/orders | 使用原 requestId 创建/复用订单，服务端固定价格，channel=wechat |
| POST /api/v1/membership/orders/:id/pay | 服务端查单，未支付时创建预支付单并返回 RSA 签名参数 |
| GET /api/v1/membership/orders/:id | 待支付的微信订单先向微信查询，成功则原子更新订单及权益 |
| GET /api/v1/membership/orders | 对待支付微信订单进行一次查单，再返回列表 |
| POST /api/v1/membership/wechat/notify | 原始报文验签、AES-256-GCM 解密、核对交易并确认权益，成功返回 204 |

前三类用户操作沿用微信登录 Bearer 鉴权，只能操作自己的订单。支付参数只含 `timeStamp`、`nonceStr`、`package`、`signType`、`paySign`。小程序调用 `uni.requestPayment`（微信平台下对应普通 `wx.requestPayment`），然后读取订单和权益；客户端回调成功不直接开通会员。

取消收银台保留 pending 订单，刷新后可继续支付。网络超时不会自动重发付款。订单有效期两小时；过期时先核对/关闭微信订单再将本地记录关闭，用户可创建新订单。重复 requestId 和账户锁阻止同账户产生多笔当前待支付订单；重复支付通知不重复授予权益。商户号、AppID、付款人 OpenID、金额、币种和微信交易号都须匹配。微信 API 应答及回调都验签，过期签名、探测签名和未知公钥 ID 被拒绝。

真实支付启用后禁止模拟开通和模拟撤销，历史模拟订单仍可查看。真实退款尚未接入：不能用“撤销模拟权益”处理真实付款。正式开放前须确定商户退款流程并补齐退款通知与权益回收；如在商户平台人工退款，当前代码不会自动撤销权益。

## 验收

自动化用本地生成的 RSA 密钥、签名应答和加密回调验证，不使用真实密钥、不访问微信支付网关、不扣款。覆盖请求/调起支付签名、回调验签/解密、金额与账号校验、幂等确认、查询恢复、客户端取消与账号切换。

上线前还需要微信真机小额订单验证：付款、回调到达、查单、权益开通、重复回调与取消。当前未提供商户参数，未执行真机交易，也未部署线上服务。

官方依据：[小程序下单](https://pay.wechatpay.cn/doc/v3/merchant/4012791897)、[调起支付签名](https://pay.wechatpay.cn/doc/v3/merchant/4012365341)、[APIv3 签名验签](https://pay.wechatpay.cn/doc/v3/merchant/4012365342)、[微信支付公钥验签](https://pay.wechatpay.cn/doc/v3/merchant/4013053249)。
