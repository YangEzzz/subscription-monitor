# 会员与订阅额度配置

后台「数据概览 → 会员与订阅额度」可保存会员开关和免费用户订阅数量上限。默认关闭会员、上限 10。服务端每次请求读取数据库，无进程内缓存；多实例共享配置。

关闭时所有用户按配置额度执行；隐藏会员卡片及升级入口，不能创建会员订单或发起支付。原会员记录和全部已有订阅保留。超出上限只限制新增和恢复，编辑、提醒、删除不受影响；删除释放额度。暂停、到期订阅仍计数，演示与已删除订阅不计数。

开启后恢复会员权益。免费用户达到上限时，仅在支付及当前设备可用时进入会员引导，否则提示删除释放位置。已支付订单的查询、回调、发货与退款不受会员开关影响。

小程序回前台及新增、保存前刷新额度。无需常驻轮询；停留中的页面不会瞬间消失。配置加载失败时隐藏会员入口，新增提示重新读取；服务端始终负责额度校验。

## 首次部署

1. 备份数据库后执行 `pnpm --dir backend db:deploy`，应用 `202610300001_runtime_policy` 迁移。必须先迁移再启动新版后端。
2. 构建并部署后端、管理后台。
3. 通过 HBuilderX 编译并发布包含动态配置逻辑的小程序。此后修改配置无需重新发布小程序。
4. 默认关闭会员、统一 10 条；用测试账号确认第 11 条受限、删除可释放，后台修改上限后立即按新额度校验。

仅部署源码没有改变远程数据库。本地 `start:local` 默认只读，禁止修改此配置，需在可写后台保存。

## 服务器更新命令

代码推送后，在服务器执行以下命令。任一步失败即停止，不继续启动新版本。

```bash
cd /opt/subscription-monitor
set -euo pipefail
umask 077
git pull --ff-only origin main
sudo docker compose --env-file deploy/.env.production config --quiet
mkdir -p backups
sudo docker compose --env-file deploy/.env.production exec -T postgres \
  sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' \
  > "backups/pre-membership-policy-$(date +%Y%m%d-%H%M%S).dump"
sudo docker compose --env-file deploy/.env.production build api admin
sudo docker compose --env-file deploy/.env.production run --rm migrate
sudo docker compose --env-file deploy/.env.production up -d --no-deps --force-recreate api admin
sudo docker compose --env-file deploy/.env.production ps
curl --retry 12 --retry-delay 5 --retry-connrefused -fsS http://127.0.0.1:3001/api/v1/health
sudo docker compose --env-file deploy/.env.production logs --tail=80 api admin
```

确保生产配置已启用 `LOCAL_ADMIN_ENABLED=true`。迁移后首次读取配置默认为会员关闭、上限10，无需手工插入配置行。
