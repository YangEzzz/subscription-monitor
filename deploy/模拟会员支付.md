# 模拟会员支付

2026-10-01：永久会员标价 ¥29.90。当前仅模拟支付，不调用微信收银台，不收款；成功结果会在后端保存测试会员权益。

## 服务器开启

代码推送后在服务器执行：

```bash
cd /opt/subscription-monitor
git pull --ff-only
sed -i '/^MEMBERSHIP_SIMULATION_ENABLED=/d' deploy/.env.production
echo 'MEMBERSHIP_SIMULATION_ENABLED=true' >> deploy/.env.production
sudo docker compose --env-file deploy/.env.production up -d --build
sudo docker compose --env-file deploy/.env.production ps -a
sudo docker compose --env-file deploy/.env.production logs --tail=80 migrate api
```

本次新增数据库迁移：为 memberships 增加权益来源和来源订单号，新增 membership_orders 表，不删除已有账号、会员或订阅。Compose 的 migrate 服务先执行迁移，成功后 API 启动。确认 migrate 成功退出、API 健康，再重新编译并运行小程序源码。

本地开发在 backend/.env 设置同一变量并启动后端。默认 false，未开启时页面显示“模拟支付暂未开放”，所有模拟写接口返回 403。订单及已有测试权益仍可查询，关闭开关不会自动撤销已经发放的权益。

## 测试步骤

1. 在“我的”进入“会员中心”，读取账号额度和标价，确认“模拟支付，不会实际扣款”提示。
2. 创建订单，在同页模拟收银台选择成功、取消或失败。
3. 成功后后端保存永久测试权益，免费 5 条限制解除；已是会员不能再次下单。
4. 取消或失败不授予权益，可以新建订单重试。网络异常先刷新订单与权益，不自动重发写请求。
5. 重新打开页面或同一微信账号重新登录，订单和会员权益仍从后端读取。
6. 已完成订单可“撤销模拟开通”，页面内确认后撤销该订单的测试权益；原有订阅不删除。撤销后可重新购买。再次撤销旧订单不会影响后续新订单权益。
7. 本地 HTML 后台的“会员权益”“会员订单”可查询跨账号的来源、状态及订单金额；此只读查询范围已获用户授权，后台没有新增支付写接口。

## API

所有订单接口都使用现有微信登录 Bearer 身份，用户只能查询和操作本人订单。

| API | 用途 |
| --- | --- |
| GET /api/v1/membership | 账号权益、数量额度、lifetime、来源及模拟商品配置 |
| GET /api/v1/membership/orders | 最近 50 条本人订单 |
| GET /api/v1/membership/orders/:id | 本人订单详情 |
| POST /api/v1/membership/orders | { productId: "lifetime", requestId: "16 至 80 位字母数字下划线横线" } |
| POST /api/v1/membership/orders/:id/simulate | { outcome: "success" / "cancel" / "failure" } |
| POST /api/v1/membership/orders/:id/simulate-refund | 撤销已完成模拟订单的测试权益 |

订单金额以整数分保存（2990），在本人页面显示 ¥29.90；HTML 管理查询为展示金额转换为 29.9 元。商品/渠道固定为 lifetime/simulation；客户端提交额外金额字段会被白名单剔除。重复 requestId 返回原订单，不同 requestId 在已有待支付订单时复用待支付订单。

模拟成功在同一个按账号加锁的数据库事务中更新订单和权益，重复成功/撤销请求幂等。创建和恢复订阅同样按账号加锁，避免并发超过免费额度。

## 后续接真实支付

真实支付需单独接入渠道下单、验签回调、主动查单和退款确认。上线真实支付前关闭模拟写开关，模拟订单仍保留 simulation 标记。当前测试权益不得伪装成真实付款，应制定保留或撤销策略并按来源处理；旧会员来源记为 legacy。当前代码不包含真实收款能力。
