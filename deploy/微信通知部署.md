# 微信续费通知部署

模板：`DtXtPe3WigMtfa07tmFI5fkXHVwY1hh5wex7wdLh3to`。
`time22` 填扣费日期，`amount4` 填记录中的预计金额。消息属于提醒，不证明实际扣款。
还款时间只使用记录中的日期，不虚构具体扣款时刻；上线后验证微信对 time22 的实际校验及投递结果。
确保此长期订阅模板已经添加到 AppID `wx639160564da9289a` 的订阅消息列表。

在服务器项目目录执行（之前配置的 AppSecret 和 AUTH_TOKEN_SECRET 保留）：

```bash
cd /opt/subscription-monitor
git pull --ff-only
python3 - <<'PY'
from pathlib import Path
path = Path('deploy/.env.production')
updates = {
    'WECHAT_REMINDER_TEMPLATE_ID': 'DtXtPe3WigMtfa07tmFI5fkXHVwY1hh5wex7wdLh3to',
    'WECHAT_SUBSCRIPTION_TYPE': 'long_term',
    'WECHAT_MESSAGE_STATE': 'formal',
    'NOTIFICATION_SCHEDULER_ENABLED': 'true',
}
lines = path.read_text().splitlines()
lines = [line for line in lines if line.split('=', 1)[0] not in updates]
lines.extend(f'{key}={value}' for key, value in updates.items())
path.write_text('\n'.join(lines) + '\n')
PY
docker compose build api migrate
docker compose run --rm migrate
docker compose up -d --no-deps --force-recreate api
docker compose logs --tail=60 api
```

数据库迁移增加微信身份、授权记录和通知记录，不能省略。
使用 PostgreSQL 持久化时每分钟检查一次，依据用户时区和提醒时间发送。
内存模式不自动发送；不能用于线上通知。

重新编译并发布小程序；开发版测试可将 `WECHAT_MESSAGE_STATE` 改为 `developer`，体验版用 `trial`，正式版用 `formal`。
如果微信返回 IP 不在白名单的错误，应在公众平台后台配置服务器的公网出口 IP。

新模板为长期订阅，`WECHAT_SUBSCRIPTION_TYPE=long_term` 启用长期授权；未设置时仍使用一次性模式。
用户进入“我的 → 续费通知”点击允许，一次授权可持续接收提醒。更换模板后需要对新模板重新授权，旧模板授权不继承。
暂停发送保留长期授权，点击可恢复；用户拒绝、关闭微信消息或微信返回授权失效时会停止发送。
默认在用户本地时间 09:00 发送；未填写金额、暂停、取消、归档、删除和演示记录不发送。
错过提醒节点时只处理当前最新可用节点，不补发全部历史节点；扣费日已过不发送。

“通知发送记录”展示最近发送结果。微信明确拒绝时保存错误码；授权失效 `43101` 会暂停通知，要求重新授权。
明确的临时失败最多尝试三次；超时或中断后的发送结果未知不自动重发，长期授权保留，但不会重发结果未知的同一条消息。
点击消息打开对应订阅；若账期已变更会提示显示的是最新账期。

代码和模拟接口测试不代表微信实际投递成功。上线后使用自己的账号授权，并在提醒时间查看微信消息与发送记录完成验证。
