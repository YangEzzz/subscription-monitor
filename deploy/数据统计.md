# 管理后台数据统计

入口：后台左侧「数据统计」，支持近 7／30／90 天、指标切换、键盘逐日查看及每日明细。接口为独立管理服务的 `GET /stats?days=30`，必须有管理员会话。

## 指标口径

- 新增账号：`app_users.created_at`，微信首次成功登录创建账号；历史按当前保留账号统计，不能与微信平台累计用户数直接等同。
- 活跃：成功登录或通过认证的业务请求。`user_daily_activity` 每个用户、每个北京时间自然日保留一条，记录首次与最近访问时间；相同日期更新间隔至少 60 秒，不保存 IP、请求内容或 token。管理员读取、公共接口及支付回调不计入。DAU 是今天，WAU／MAU 是截至今天的 7／30 天去重用户，区间活跃按选定范围去重，不能累加每日人数。
- 留存：注册批次在第 1／7／30 天有业务访问的人数除以该批次账号数。只纳入已经结束且位于采集首日之后的观察日；整体留存按可计算批次人数加权。未到期或没有历史采集时为 null，页面显示「—」。采集首日及今天不是完整自然日；活跃窗口尚不足时显示已采集部分。
- 新增订阅：按创建日期，排除示例，保留软删除记录；不是用户订阅支出金额。
- 付费：渠道 wechat／virtual、币种 CNY、有 paid_at 的 paid／refunded 订单按付款日统计，包含后来退款的付款记录。退款单独按成功凭据及平台日期统计，净额为期间支付减退款，可为负数。金额以整数分汇总；付费人数跨订单去重。完整规则见[收支与测试账号统计](收支与测试账号统计.md)。
- 新增账号付费转化：所选期间新增账号中，也在所选期间有上述有效支付的账号数／所选期间新增账号数。无新增账号时为 null。

账号删除会级联删除该账号的活跃与业务记录，因此这些是基于当前保留记录的运营统计，不是不可变的财务或审计账本。没有采集的历史不能回填；采集后没有记录的日期显示零，并不证明期间服务从未中断。

## 上线与本地开发

增量迁移：`20261024010000_daily_activity`，只新增表和索引。数据库已经应用此迁移，生产应用仍需要部署本次后端代码后才开始记录；创建表本身不会使旧版本自动采集。

`ANALYTICS_COLLECTION_ENABLED=true` 默认启用生产采集。需要暂停时设为 false。无需定时任务，数据由用户访问落库并由管理接口汇总。采集失败不阻断登录和业务请求，后端输出 `Daily activity recording failed` 供排查。

本地 `node scripts/start-local.cjs` 强制关闭活跃采集及其他后台任务，默认只读连接远程数据库；不需要每次开发都部署。管理端使用本地后端获取真实历史数据。

核验脚本：在 backend 下运行 `node scripts/verify-admin-stats.cjs`，只读连接，使用临时 CTE 测试数据验证 SQL 的去重、支付过滤、留存成熟期、空历史及 7／30／90 天窗口；不插入测试记录。
