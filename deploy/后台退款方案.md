# 后台退款方案与实现

入口：会员订单 → 订单详情 → 退款处理。先从微信查原支付单，核对支付平台、状态、交易号、金额及可退余额，再填原因、核对订单并明确确认。后台记录操作人、原因、退款单号和处理进度。

第一期只支持虚拟支付普通订单的全额退款。iOS 由用户向 Apple 申请；模拟支付没有实际款项；历史普通微信支付渠道到原支付平台办理；已发生部分退款或剩余可退金额不等于全额的订单不再自动发起，避免重复或超额退款。

依据微信官方 [启动订单退款任务](https://developers.weixin.qq.com/miniprogram/dev/server/API/VirtualPayment/api_refund_order) 和 [查询订单](https://developers.weixin.qq.com/miniprogram/dev/server/API/VirtualPayment/api_query_order)，以及腾讯云官方 [虚拟支付接入说明](https://github.com/TencentCloudBase/skills/blob/main/skills/cloudbase-wechat-integration/references/virtual-payment.md)。官方页面本次已直接读取核验：退款只启动任务；订单状态 5 是商户侧扣款完成，8 才是用户侧收款完成，7 是退款失败；退款单用自身退款单号查 query_order，不将原支付单的 refund_fee 当作累计退款金额。

## 状态与一致性

1. 校验管理员会话、JSON 请求、原订单号和整数分金额。操作人取当前登录账号，客户端不能指定。
2. 新鲜查单确认 order_type=0、支付状态为已付、交易号及原金额一致、left_fee 等于全额，并在支付后 365 天内。iOS／未知平台类型拒绝。每次提交重新核对，不信任页面旧值。
3. 按用户事务锁，在请求微信前创建 membership_refunds 记录，order_id 唯一；退款单号为固定生成的 32 位标识。重复和并发点击复用原记录，只请求一次微信。
4. 发起 refund_order，使用已有的支付签名机制，环境固定正式 0、客服来源 1。核对返回的退款单号、支付单号和交易号。errcode=0 仅表示受理，状态为 processing，不改订单和权益。
5. 超时、网络失败、返回内容不匹配或未能核实受理结果，标记 unknown，保留原单号，绝不换号重退。服务重启后从持久化表恢复，每 5 分钟只查退款进度；可手动点击「查询退款进度」。未找到原退款单也不自动重发，需到微信平台人工核查，避免已经受理但查单暂不可见时重复退款。
6. 查询退款单自身的状态并核对金额，状态 5 继续等待，状态 8 才执行原有退款确认事务；经过签名验证的退款成功推送也可确认。只有原权益的 sourceOrderId 对应该订单时才撤销会员，保留其他来源或较新订单权益。退款记录完成、订单 refunded 与权益变更在同一用户事务内保存。
7. 明确退款失败保留 failed 与原退款单号，订单仍为 paid、权益保留；在微信平台核查，不自动新建退款。部分退款继续保留永久会员，第一期不提供后台部分退款入口。

## 接口

- GET `/refunds/:orderId`：查询退款条件与持久化记录。
- POST `/refunds/:orderId`：`{amount, reasonCode, reason, confirmOrderId}`。amount 为整数分，reasonCode 为 1–5，原因 2–200 字。返回持久化状态，客户端据此显示受理／待核实，不把 HTTP 200 当作退款完成。
- POST `/refunds/:orderId/check`：查询原退款单并同步确认结果。

这些接口仅在独立管理员服务，沿用来源校验和 HttpOnly／SameSite Strict 会话，不对小程序用户开放。退款请求限制 JSON、4096 字节；前端要求单独的核对确认步骤，提交中禁用按钮。

## 部署与验证

增量迁移 `20261025000000_membership_refunds` 已应用，只创建退款记录表，不办理实际退款。需部署本次 API 和 admin 才能在生产后台操作。原部署配置需包含有效管理员账号和虚拟支付参数；`ADMIN_REFUNDS_ENABLED=false` 可禁用退款，虚拟支付关闭时同样禁用。开发启动器强制关闭退款，远程数据库保持只读。

本次仅用假微信接口验证受理、重复请求、并发、超时恢复、状态 5／7／8、iOS／未知类型、余额与金额不匹配、权限和权益归属。没有调用生产退款接口，尚未完成真单退款验收。上线后应由管理员选定订单，在确认金额及退款对象后完成一次真实退款验收。

`node scripts/verify-admin-refunds.cjs` 以只读连接核验查询与 INSERT 的 EXPLAIN，不写测试退款记录。最新收支统计改为保留原付款日的金额，独立记录成功退款及日期；统计不会因退款抹掉原支付记录，详见《收支与测试账号统计》。

## 今日数据与通知展示

概览和统计页首屏独立显示北京时间今天的新增账号、去重活跃、支付订单和有效支付金额，补充新增订阅／付费人数；累计与所选区间汇总单独标明。不再显示本地连接、存储类型、通知配置或定时任务开关。

通知保留每次调用结果：微信 errcode=0 展示「微信已受理」，明确拒绝展示失败与错误码，网络超时展示结果待核实。不声称已送达／已读，不因没有失败记录就显示「通知正常」。通知历史仍从所属用户查看。
